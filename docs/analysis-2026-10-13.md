## 1. What the repo is, and what actually happens at render time

The starter is small: `engine/main.py` loads every `input/*.json`, calls `resize(source, target_canvas)` from `engine/resize.py` (currently a uniform stretch), runs a loose structural self-check, writes `output/<task>_output.json`, then renders a PNG through `renderer/converter/` (the team's vendored adaptation of the organizers' *transformer-convertor*) wrapping CyberAgent's `cr-renderer`. Scoring runs the same image under `--network none` on linux/amd64, on an Apple M5 Pro (so under emulation).

Everything below was verified by reading `cr-renderer` source and by rendering experiments, not from the docs.

**Text (decides most of the engine design)**

- The converter does the word-wrap itself (`renderer/converter/wrap.py`: greedy, breaks only at ASCII spaces, a long word overflows, `letter_spacing` ignored while wrapping but added at draw time). cr-renderer only draws the newlines it is given.
- cr-renderer builds `skia.Font(typeface, int(fontSize))`: **glyphs are drawn at the integer part of `font_size`**, line pitch uses the float, wrap used the float. Fractional sizes make the three disagree. `font_size` in (0, 1) draws nothing.
- Text is **top-aligned** at `y`; line *i* baseline is `y + i·fs·line_height − fAscent`. **Box height is never used**: no clipping, no centering, `max_lines` ignored. Block height = `(N−1)·fs·lh + (fDescent − fAscent)`; validated to ≤2.5 px against rendered ink.
- Element `opacity` has **no effect on text**; only the alpha inside `color: rgba(...)` does. `style_runs.end` is treated as **inclusive**.
- A text element with `width/height/font_size/line_height ≤ 0` raises inside the renderer; `main.py` catches nothing, so **one bad element aborts every remaining task in the run**.
- Legibility at 1× on the dark gradient: Sans Bold caps ≥8 px, Sans Regular ≥9 px, Serif Bold ≥10 px, low-alpha text +2 px. Canvases over 2048 px are **downscaled** in the PNG (A4 renders at 0.58×), so floors must be computed in "judge pixels".
- **Platform difference (new, verified):** on macOS skia uses CoreText (fractional advances); in the Linux container it uses FreeType (integer-rounded advances). Same text, same font, same size: 279/279 fractional advances locally vs 0/279 FreeType-backed, and the summed width differs by +8.5 % at 10 px, +3 % at 23 px. Wraps flip in roughly 1 case in 10 under uniform scaling. Consequence: local and Docker JSON will not be byte-identical for any measured fit, and the official render's backend is unknown.

**Geometry, images, shapes**

- Rotation is about each element's own centre; the drawn footprint is the rotated AABB `W' = w|cos θ| + h|sin θ|`, `H' = w|sin θ| + h|cos θ|` (ribbon 300×54 @ −12° → 304.7×115.2; the source ribbon already pokes 0.6 px above the canvas). Off-canvas parts are clipped silently; the self-check tests only the unrotated box.
- A grouped rotated shape + label stays aligned only under **uniform** scaling about a shared centre.
- The canvas is **cleared to white** before drawing. Any uncovered area is white, which makes the white logo wordmark and white text vanish. `fit: cover` backgrounds crop to the middle band of the gradient on wide targets.
- `contain` images never distort (letterboxed inside the box), so box aspect changes are pixel-safe but still fail the "~5 % proportion" structural rule if measured on the box. The bottle and logo assets carry ~60 % transparent padding.
- Shapes are Pillow rasters stretched into the box: `corner_radius` clamps to `min(w, h)/2` (pills stay pills), strokes are ignored except for `line`, whose stroke width does not scale.
- Missing assets draw a grey box with a 2 px red border and a fixed-size label that becomes red garbage below ~160 px wide. z-order is a stable sort with missing `z_index` = 0; a string `z_index` crashes the converter.
- Rendering costs 40–450 ms per task locally; the engine's own budget is effectively unconstrained (text measurement is ~0.004 ms per call once the typeface is cached).

**Harness and deployment**

- `requirements.txt` is unpinned (`git+https://…/cr-renderer` at HEAD). The resolved py3.11/amd64 wheel set is 43 wheels / 118 MB; `skia-python 144.0.post2` ships manylinux_2_28 wheels (fine for `python:3.11-slim`, which is Debian trixie).
- Importing the converter at run time is network-free (0 socket attempts with connect monkey-patched) and ~0.5 s, already paid by `main.py`.
- No Python 3.11 on this Mac (venv and Anaconda are 3.13). PEP 701 f-strings are the trap `ast.parse(feature_version=(3,11))` does not catch.
- No `.dockerignore`; `.venv` (341 MB) is inside the build context. The Dockerfile copies the whole `engine/` tree.
- The brand kit README says both fonts and assets are **placeholders that will be swapped with the same filenames**, so no per-face or per-asset constant may be hard-coded.

## 2. Assessment of Joonseo's iteration-1 plan

The plan is strong: every factual claim R1–R14 checks out, the architecture is the right one, and the unresolved items U1–U12 are the real ones. Four adversarial critics produced 40 findings; a per-finding refutation pass killed 29 of them. What survived:

**Omissions (add)**
1. Integer font sizes and the int/float measurement split (not mentioned anywhere).
2. The white canvas clear and its consequence for the logo.
3. The CoreText/FreeType difference, which makes the DoD line "Docker output identical to local" unachievable as written.
4. Asset ink boxes (plan P7 "never open asset files" costs ~25 % of a leaderboard's width).
5. A sanitize step and a final clamp that run on *every* path including the fallback; both proposer prototypes' fallbacks raised or collapsed on malformed input.
6. Implicit containment units (an ungrouped pill that contains a label) promoted from P1 to P0 — a likely hidden-test pattern.
7. The viewer add-on, CI, `.dockerignore`, pinned requirements, repo visibility.

**Rules that would hurt (change)**
- `_enforce_hierarchy` as strict source font-size order over *all* text caps the CTA label at the long headline's size on strips. Enforce order (lowering only) among free-standing text only; size labels from their pill with a ~1.3× cap; siblings equal.
- S1 readability as a binary 12 px share cannot rank candidates on tiny canvases (three distinct values across six plausible 728×90 layouts). Use a continuous ramp in judge pixels.
- Decorations mapped by normalized centre then clamped: the L2 corner circle becomes a detached disc overlapping the badge. Corner-pin decorations that hugged an edge; keep bleed behind a flag until Q1 is answered.
- `_repair` is unreachable (lane candidates cannot fail the gates except via bugs) and cannot fix the one case it is reached for. Replace with per-element projection + a staged fallback.

**Over-engineering (drop for iteration 1)**: Kendall-τ (S3), spacing CV (S6), alignment share (S7), sibling_set as a separate concept (free side effect of a common scale), corner-pinned candidate variants (make it one post-step), the Pillow fallback.

**Scheduling**: the "two developers idle" critique was refuted by simulating the dependency graph (~0.5 session idle total). The real imbalance is Dev 3 owning 7 of 16 P0 tasks and the whole integration chain (~7.5 sessions vs ~5). Move the contact-sheet tool or the Docker/README tasks to Dev 1/2.

## 3. Recommended architecture ("Blocks-and-Lanes", refined)

Three independent proposals were prototyped and judged under three lenses (design quality, engineering risk, robustness). Scores:

| Proposal | Design quality | Eng. risk | Robustness |
|---|---|---|---|
| Blocks-and-Lanes (refined teammate plan) | 6.0 | **8.0** | **7.0** |
| Role-Grammar (role inference + per-aspect-class grammars) | **7.5** | 6.5 | 5.0 |
| Objective-driven search (simulated annealing) | 5.5 | 4.0 | 4.0 |

Blocks-and-Lanes wins on shippability and containment; Role-Grammar produced the prettiest renders but switches layouts discontinuously at aspect-class boundaries (1200×400 vs 1200×398 moved an element 70 % of the canvas), has a single point of failure in role inference, and its fallback collapsed all elements to (0,0). The optimizer is chaotic (a 1e-9 input perturbation changed 58 of 85 fields) and would be slow under emulation. The grafts below take the best of the other two.

**Pipeline of `resize()`**

0. **Sanitize** a deep copy: `float()` with schema defaults for `x, y, width, height, font_size, rotation(0), opacity(1), line_height(1.2), letter_spacing(0)`; `int(z_index)` default 0; replace None/str/NaN/inf. Canvas = `{width:int, height:int}` from those two keys only (hidden `target_canvas` may carry a format name). Everything runs inside `try/except Exception`.
1. **Units**: one per non-null `group_id`, singletons otherwise; **implicit containment** (an ungrouped opaque shape < 30 % of canvas that contains ≥ 90 % of a higher-z text's ink box, smallest container wins, never a decoration). Unit box = union of members' rotated AABBs.
2. **Classify by geometry only**: background (lowest-z image/shape covering ≥ 90 %, or ≥ 60 % with `fit: cover`), decoration (shape-only, effective alpha ≤ 0.5 or bleeding past the source canvas), content. **Furniture flags**: corner-anchored (area < 3 %, within ~6 % of two perpendicular edges, tested on ink), legal line (long, small, low-alpha, bottom), watermark (tiny bottom-corner image). Nothing may branch on ids, asset names, content strings or exact canvas sizes.
3. **Measure** every text once per integer size via the converter's own `char_widths` + `wrap_text` (lazy import, try/except), with a cached typeface per face; asset ink rects from alpha bbox (read-only, cached, full-box fallback). Ink boxes feed reading rows, collisions, spacing.
4. **Near-identity fast path**: if `|AR_t/AR_s − 1| < 3 %` → pure uniform scale (fonts too, integer); 3–15 % → uniform scale + anchor adjustment; otherwise candidates.
5. **Candidates**: *anchor* (normalized centres, `min(sx, sy)`, deterministic push-apart along the flow axis, block compaction, floor relaxation) and *lanes* over reading-order blocks (every contiguous partition, k ≤ 4, cap ~120; columns for wide targets, stack for tall; common scale found by binary search, capped at `max(sx, sy)`; per-unit floor-first scaling `ks = max(k, floor/fs_max)`). Legal line reserved as a bottom band; watermark and corner-anchored units pinned as a post-step with a collision check and revert.
6. **Fit**: text singletons re-wrapped to slot width at the largest integer size ≤ cap that fits ≤ 96 % of the width, longest word included, block height + one descent ≤ slot; rigid groups scaled uniformly about their centre with rotation untouched; labels-in-pills sized from the pill (`fs ≈ min(0.42·h, width that fits with ≥ 0.6 em padding)`, pill widened before label shrunk, bounded label/pill compression `r ∈ [1, 1.6]`, siblings share `fs` and `r`), re-seated at `y = cy + fCapHeight/2 + fAscent`.
7. **Project, then gate**: per element clamp sizes ≥ 1, shrink font to the longest word, shift the rotated AABB inside the canvas. Then hard gates: ids/fields, rotated bounds, image box aspect within 1 %, text fits, label inside pill, no new text-on-text ink overlap (exempt pairs that overlapped in the source), no new overlap ≥ 15 % of the smaller box between *any* two content units.
8. **Select** lexicographically: gates → sibling rows kept together → reading order and hierarchy preserved (headline adjacent to its subhead/CTA) → common scale (capped) → fewest lanes → fidelity weighted by `max(0, 1 − |ln r|/ln 2)`; then a small continuous tiebreak (readability ramp, collision-free share, utilization within 0.7–1.5× the source's ink coverage). Ties → earlier candidate.
9. **Staged fallback**: best candidate with the lightest violations after projection → anchor → the floor engine (D2). One stderr line per task: mode, candidate, floor rung, FALLBACK reason, timing.
10. **Final clamp + self-test**: integer `font_size ≥ 1`, sizes ≥ 1, finite built-in numbers, `json.dumps(allow_nan=False)`, ids == source ids in source order, every non-geometry field verbatim.

**Readability floors (one table, judge pixels `fs_png = int(fs)·min(1, 2048/max(W,H))`)**

| Size class (short side) | Top-tier free text & CTA label | Labels / bold caps | Footer / legal |
|---|---|---|---|
| micro ≤ 120 | 8 | 7 | 5 |
| small ≤ 360 | 10 | 8 | 7 |
| normal | 12 | 10 | 8 |

Per-face offsets (+1 Serif, +1 regular body, +2 for alpha ≤ 0.6) are tunables, not constants. Floors drive prominence-ordered allocation and a continuous S1 = `clamp((fs_png − 5)/7, 0, 1)`; the hard floor is 1 px; every element below target is logged. The floor ladder is explicit and few-valued (1, .85, .7, .55, .4, .25) because it is the engine's only discontinuity.

## 4. Engine rules (the contract every module follows)

1. `resize()` never raises; sanitize before analysis and again inside the fallback; the fallback touches only sanitized fields and is fuzz-tested alone.
2. Output = source ids, each once, in source order; only `x, y, width, height, font_size` (and `letter_spacing` scaled with font size) change; `content`, `font_family`, `color`, `style_runs`, `rotation`, `opacity`, `z_index`, `group_id`, `fit`, `asset_id`, `_note` keys verbatim.
3. Integer `font_size ≥ 1`; never (0, 1); never `opacity` to hide; never named colours; `text_align ∈ {left, center, right}`.
4. Measure with the converter's call path at the emitted integer size; never scale advances linearly from a reference size (FreeType rounds). Fit lines to ≤ 96 % of the box, block height + one descent. Set each text's `height` to its predicted block (the renderer never clips). Honour `max_lines` only if the source satisfied it.
5. Rotated AABB everywhere (bounds, margins, collisions), ~1 px tolerance. Groups with rotation scale uniformly about one pivot; labels stay concentric with their shape.
6. Background at exactly `(0, 0, W, H)`, fit unchanged, lowest z; never leave canvas uncovered. Non-background images keep source box aspect (1 % internal tolerance); logo never over a pill, the product, or white.
7. Decorations scale by `min(sx, sy)`, keep aspect, corner-pin when they hugged an edge, stay below content, clamp inside by default (bleed behind a TUNABLE until Q1).
8. Shapes: scale `corner_radius` with `min(w, h)`; scale `line` stroke width; pills holding text ≥ ~16 px tall; decorative shapes ≥ 3 px.
9. Missing-asset image: source aspect, ≥ ~40 px wide where possible, parked in a corner away from text and CTA; never dropped.
10. All font metrics and asset ink rects derived at runtime from `brand_kit/` (placeholder kit will be swapped).
11. Deterministic: no RNG, no set/dict iteration for ordering, scores rounded to 1e-6, source-order tie-breaks, no wall-clock cut-offs, no numpy in the scoring path.
12. Python 3.11 only (no PEP 695/701, no 3.12+ stdlib), no new runtime deps unless pinned and import-guarded, no network/subprocess/writes at run time, per-task target < 2–5 s native.

## 5. Evaluation plan

- **Targets (18, stand-in for the unpublished catalogue):** 160×600, 300×600\*, 1080×1920, 1000×1500, 2480×3508\*, 1080×1350, 1080×1080, 300×250, 1280×720, 1920×1080, 1200×628, 851×315, 1500×500, 1600×400, 1128×191\*, 320×50, 728×90, 970×90\*. Starred = **held-out**, never tuned on. Expected envelope: aspect 0.27–10.8, short side 50–3508 px. The three sample targets are exact entries of known catalogues (IAB Leaderboard, Crello "Twitter", Adobe Instagram portrait), so the hidden catalogue is a hybrid of Adobe social presets and IAB/Crello banner sizes; 1:1, 9:16, 16:9 and 1.91:1 carry most of the probability mass and must be flawless first.
- **Sources:** the three samples plus synthetic variants built from their element types (no new assets): 1080×1920 and 1920×1080 sources, no `group_id`, 1–6 badges, doubled copy, light background, 26–30 elements, renamed ids/asset ids, shuffled element order, fonts swapped for another family with the same filenames.
- **Tests that discriminated the prototypes:** byte-identical rerun in a fresh process; renamed-id invariance; shuffled-order invariance (grammar failed); ±1e-9 coordinate perturbation (optimizer failed); malformed-input exit through the fallback under `engine/main.py` (missing `font_size`, string coordinates, one-element design, NaN); neighbouring-size continuity (1200×400 vs 1200×398).
- **`tools/evaluate.py`:** runs the grid, renders source | baseline | ours contact sheets, CSV of gates/scores/floor hits/timing/fallback. Reviewed renders come from **Docker/CI (FreeType)**, not macOS.
- **Optional (P2):** a dev-time Claude-vision judge scoring pairs of renders against the five rubric rows (~$0.02 per judgment). Allowed (rules constrain runtime only), useful as a regression signal and for tuning the few tunables, but not a pillar.
